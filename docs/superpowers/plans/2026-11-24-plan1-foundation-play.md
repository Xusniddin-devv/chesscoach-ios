# ChessCoach iOS — Plan 1: Foundation + Play vs Bots

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A TestFlight-shaped iPhone app where you pick a bot, play a full game against on-device Stockfish 18 in Training or Silent mode, and get the web app's exact move grading and plain-English explanations — in the approved Charcoal & Signal Orange identity with Liquid Glass navigation.

**Architecture:** Two local Swift packages hold everything testable with plain `swift test` on macOS: `ChessCore` (pure Swift: rules adapter over chesskit-swift, engine result types, classifier, motifs, explanations, accuracy, levels, board geometry, game session) and `StockfishKit` (vendored Stockfish 18 C++ + a C bridge + a Swift `actor` speaking UCI). A thin SwiftUI app target (generated by XcodeGen) renders the design system, board and screens and wires `StockfishKit` into `ChessCore`'s `ChessEngine` protocol.

**Tech Stack:** Swift 6.3, SwiftUI (iOS 26 Liquid Glass), Observation, SwiftData, chesskit-swift 0.17.0 (MIT), Stockfish 18 (`sf_18`, GPLv3), XcodeGen, XCTest/Swift Testing.

**Spec:** `docs/superpowers/specs/2026-11-24-chesscoach-ios-design.md`. Exact grading rules: `docs/reference/web-rules.md` (recovered from the live web bundle — the source of truth for every number in Tasks 2 and 5–8).

## Global Constraints

- iOS deployment target **26.0**; iPhone only; portrait only; dark appearance forced (`.preferredColorScheme(.dark)`).
- Swift 6 language mode, strict concurrency complete.
- License **GPLv3**: `LICENSE` file at repo root (GPL-3.0 text); every dependency must be GPL-compatible. Never name the app or a feature "Stockfish"; "Powered by Stockfish" allowed.
- Bundle ID `uz.xq.chessc`; App Store name "ChessC - Chess Coach"; home-screen display name (`CFBundleDisplayName`) "Chess Coach".
- No secrets in the repo. NNUE files are fetched by script and gitignored.
- Grading numbers come only from `docs/reference/web-rules.md`; changing one requires changing its golden test in the same commit.
- `analysisVersion = 1` (iOS lineage).
- Explanations: no LLM, no network.
- Design tokens (verbatim from spec): background `#131516`, surface `#1D2022`, surface-2 `#2A2E31`, text `#ECEEEE` (secondary ≈60% opacity), accent `#FF6A1A` / pressed `#CC4F0C` / on-accent `#FFFFFF`, danger `#FF3B46`, board light `#D6D9D8`, board dark `#7D8483` (must not read green).
- Anti-slop list (applies to every UI task): no gradients, no purple, no neon, no emoji as icons, no default SF-Symbol icon grids, no centered hero + 3 cards, no filler marketing copy, no glass on content cards. Liquid Glass only on bars, floating controls and sheets.
- Engine: one `go` at a time per engine instance; always send full move history (`position fen <start> moves …`); mate scores never flattened before `toCp`.
- Training-mode level = the player's estimated rating; Plan 1 has no rating yet, so use a constant `PlayerProfile.defaultRating = 800`.

## Review Focus

1. Player taps moves faster than grading finishes (Silent mode) → every move is graded in order against its own history; none dropped or duplicated.
2. Take back while a grade or bot search is in flight → the stale result is discarded; board, move list and verdicts stay consistent.
3. Promotion (including under-promotion), en passant and castling made through the board → correct UCI to engine, correct SAN, correct piece animation.
4. Game ends (mate, stalemate, threefold, fifty-move, insufficient material) → no engine request for a bot move in a finished position; `bestmove (none)` from the engine never crashes.
5. App goes to background mid-search / engine throws → session surfaces a retryable state, no hang, no crash; engine restarts cleanly.

Each line has a test in the owning task: 1–2 → Task 10; 3 → Tasks 1, 8, 10; 4 → Tasks 4, 10; 5 → Tasks 4, 10.

### Task 10: GameSession (play loop, grading queue, takeback, end)

**Files:**
- Create: `Play/GameSession.swift`
- Test: `GameSessionTests.swift` (with `FakeEngine` in the test target)

**Interfaces:**
- Consumes: everything in Tasks 1, 2, 5–9.
- Produces: `@MainActor @Observable public final class GameSession`
  - `init(bot: Bot, userColor: Piece.Color, mode: PlayMode, engine: ChessEngine, playerRating: Int = PlayerProfile.defaultRating, analysisDepth: Int = 16, startFen: String = Rules.startFen, clock: any Clock<Duration> = ContinuousClock())`
  - state (read-only): `fen: String`, `moves: [String]`, `sans: [String]`, `tracker: PieceTracker`, `verdicts: [Int: Verdict]` (key = ply, 1-based), `phase: Phase` where `enum Phase: Equatable { case userTurn, botThinking, grading, interrupted(Verdict), over(GameResult, reason: GameState?), engineError }`, `lastMove: (from: Square, to: Square)?`, `bestArrow: (from: Square, to: Square)?`
  - `func start()` — if bot moves first, request bot move
  - `@discardableResult func userMove(_ uci: String) -> Bool` — synchronous: validates with `Rules.apply` against current `fen`, applies immediately, enqueues a grade job carrying a snapshot (`fenBefore`, `fenAfter`, `startFen`, history before/after, ply, generation); returns false if illegal or not user's turn
  - `func takeBack()` — undo back to the user's previous turn (removes bot reply too), increments `generation`, clears verdicts for removed plies
  - `func showBest()` — sets `bestArrow` from the interrupting verdict's `bestMove`
  - `func continueAfterInterrupt()`
  - `func resign()`
  - `func hint() async` — Training mode only, on the user's turn: analyze the current position (depth `analysisDepth`, MultiPV 1, full history) and set `bestArrow` to its best move
  - `func retry()` — from `.engineError`, re-runs the failed step
  - `func snapshot() -> GameSnapshot`
- Behavior:
  - Grade = two `analyze` calls (before/after) at `analysisDepth`, `multiPV: 2`, with full history; engine cache makes the second move's "before" free.
  - Grade jobs drain strictly in order; a job whose `generation` ≠ current is dropped on completion.
  - **Training:** after a user move, phase `.grading`; bot replies only after that move's grade; if the interrupt rule (Task 2) fires → `.interrupted(verdict)`; `continueAfterInterrupt()` → bot move.
  - **Silent:** bot replies immediately; grades run in the background queue.
  - Bot move: `opponentMove` then wait `thinkTimeMs(elo:jitter:)` minus elapsed (pad only if search finished early), using the injected clock.
  - After every applied move compute `Rules.state(fen:history:)`; terminal → `.over`; never request a bot move in a terminal position.
  - Engine throws → `.engineError`; `retry()` resumes.
